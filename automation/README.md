# LP要件定義キュー：検証用セットアップ

このディレクトリのApps Scriptは、**Google Sheetsに紐づく既存のApps Scriptプロジェクト**に追加して実行します。GitHub ActionsやGitHub Pagesへのデプロイ機能ではありません。

## 目的
- `LP制作入力` シートに登録された情報から、要件定義を作るためのプロンプトと不足情報を整理する。
- 作成したプロンプトを同じ**非公開の検証用スプレッドシート**の `LP要件定義キュー` に保存する。
- 初期ステータスは常に **未承認**。要件定義文書はまだAIに送信・生成されない。
- 制作許可が確認できない場合は制作禁止と表示する。

## テスト手順
1. 検証用スプレッドシート `ミセミルWeb_業務自動化_検証用_v1` を開く。
2. 「拡張機能 → Apps Script」に進む。
3. 新しいスクリプトファイル `MisemiruRequirements.gs` を作り、`automation/MisemiruRequirements.gs` の内容を貼る。
4. 保存し、関数 `misemiruPrepareLpRequirements_v1` を手動実行する。
5. `LP要件定義キュー` の結果と未確認事項を点検する。

## 安全性
- 明示的な許可・利用権の検証なしに顧客LPの実装や公開を進めない。
- 店舗の名前、Instagram、URL、写真、メニュー等を**GitHubの公開リポジトリにコミットしない**。店舗ごとの入力と生成プロンプトは非公開シートで管理する。
- このコードは外部サイトの内容取得やChatGPTへのAPI送信、GitHubへの書き込み、営業DMの送信は行わない。
- 同じ店舗IDは二重登録しない。入力値更新後の再生成は、自動で既存プロンプトを上書きせず、確認してから手動で行う。

## 後続の工程
事実確認とオーナーの承認が得られた要件定義からのみ、デザイン定義 → デザイン審査 → リファレンス画像 → Codex実装 → QA/レビュー → GitHub Pagesの共有用サンプルURLへ進む。顧客へのURL送付は人間が担当。
