# Codex operating rules — ミセミルWeb sample LPs

## Purpose and authority
This repository is a fictional test of the **GitHub Pages sample LP** process, not the customer's production site.
Prioritize current user instructions and verified client-specific requirements, then the team's LP SOP.
Before implementing a real client, ask only for blocking facts. Mark other unknowns as pending instead of inventing them.

## Mandatory sequence
1. Confirm **express permission for sample production** and permissions for each photo, logo and identifiable person.
2. Research official website, official Instagram and direct messages first; use Maps, Tabelog and third-party listings as leads, not final proof for changing details.
3. Separate **verified facts**, **design hypotheses** and **unverified information** with dated sources.
4. Produce and review a high-quality `requirements.md` (audience, offer, primary CTA, sections, sources, missing facts, acceptance criteria).
5. Produce and critically review `design-definition.md` with design and engineering perspectives. Improve before section references.
6. Prepare approved reference images and web assets; keep original private images outside this public repository.
7. Implement **Mobile First** on a feature branch, respecting requirements and section-by-section priorities.
8. Check visual hierarchy, typography, 375/390/768/1024/1440 widths, keyboard focus, links, metadata, noindex, lint and build.
9. Report at ~30–50% and prepare a pull request for an **independent human review**. Never merge into `main` without approval.
10. After merge and human authorization, check the actual GitHub Pages URL before customer sharing; update the CRM manually or through a reviewed integration.

## Safety and constraints
- Never invent prices, menus, reviews, opening hours, address, availability, booking URLs, outcomes or owner consent.
- Never commit secrets, API keys, client DMs, private documents, source customer photos, or unlicensed imagery.
- Do not download and republish third-party photos without usage rights; Instagram presence does not establish permission.
- Never automate outbound Instagram cold DMs or client-facing messages.
- Do not purchase hosting or domains for free sample LPs.
- Github Pages is publicly accessible despite `robots=noindex`.
- Avoid destructive Git operations, force pushes, unrelated edits and changes to an existing customer repository.
- Four-hour **working-time target** for sample production: prioritize Hero, verified key information, primary CTA and mobile usability; reduce decoration if needed.
- Keep static-export compatibility for GitHub Pages; avoid server-only routes, Server Actions and runtime API dependencies.
